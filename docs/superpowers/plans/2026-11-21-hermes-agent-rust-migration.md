# План переноса Hermes Agent на Rust

**Цель** — первым выпустить Rust CLI с потоковым чатом, локальными инструментами, памятью и возобновлением сессий. После CLI-релиза расширить локальные возможности и выпустить отдельное настольное приложение на GPUI. Gateway, совместимость существующих клиентов и интеграции с внешними платформами входят в заключительный этап.

**Эталон** — `NousResearch/hermes-agent@2f8c1e7ed051c311af4f3b3ca0f8976b9c40839b` от 20 ноября 2026 UTC. Матрица совместимости привязана к этому коммиту. Изменения upstream после него оцениваются отдельными пакетами с собственными тестами. [Коммит upstream](https://github.com/NousResearch/hermes-agent/commit/2f8c1e7ed051c311af4f3b3ca0f8976b9c40839b)

**Предлагаемые границы** — первый CLI-релиз для Linux x86_64 с glibc и musl, затем Linux arm64, macOS и Windows. Rust должен запускать штатные сценарии без установленного Python. Существующие TypeScript/Ink и Electron-клиенты подключаются к Rust gateway по прежнему протоколу. Пользовательские Python-плагины и скрипты могут явно подключать свой интерпретатор.

**Статус** — этапы 1–3 завершены. В этапе 0 выполнены 5 из 6 пунктов. В этапе 4 опубликован CLI v0.2.0 для семи целей. Проверены запуск команд с подтверждением на macOS и обновление с v0.1.0 и откат на Linux x86_64 GNU и musl. [Релиз v0.2.0](https://github.com/tsrman/hermes-rs/releases/tag/v0.2.0), [Релизный запуск Actions](https://github.com/tsrman/hermes-rs/actions/runs/44890823373) [Релиз v0.3.0](https://github.com/tsrman/hermes-rs/releases/tag/v0.3.0) опубликован для тех же семи целей (сборки и SHA-256 проверены workflow, архив Linux x86_64 GNU скачан и сверен); обновление и откат на arm64, macOS и Windows для него ещё не проверены. В v0.3.0 вошло то, что ниже, добавленное после v0.2.0: каталог из 14 инструментов по умолчанию (включая `delegate_task` и `execute_code`), интерактивный диалог `hermes chat` без `-q`, разбор конфига по правилам эталона (`${VAR}`, именованные провайдеры, `model.api_key`, `extra_body`, `extra_headers`), токены usage, журнал отладки и живой набор задач. Подробности: [каталог инструментов](2026-11-21-tool-catalog.md), [расхождения конфига](2026-11-22-config-compat-fixes.md).

## Стратегия переноса

| Подход | Цена и условия применения |
| --- | --- |
| Взять целиком существующий Rust-порт | Быстрый старт, если совпадают контракты хранения, gateway и изоляции. Цена — принятие его архитектуры и уже внесённых отличий. |
| Поэтапно заменить Python runtime и выборочно переиспользовать Rust-код | Предлагаемый вариант. Каждый этап даёт рабочий сценарий и проверяется на одном Python-эталоне. Понадобится временно поддерживать два способа запуска на изолированных профилях. |
| Перенести все подсистемы перед первым выпуском | Обнаружение расхождений в данных, протоколе и плагинах откладывается до конца. Сложнее организовать пилот и откат. |

На первом этапе проверить `Lumio-Research/hermes-agent-rs` на коммите `9a145877` и `sheawinkler/hermes-agent-ultra` на теге `v0.22.0`. Lumio указывает в качестве эталона Python `v2026.4.13`. Ultra публикует собственную матрицу паритета и описывает отличия своего продукта. Основанием для переиспользования будут пройденные тесты выбранного эталона, стоимость устранения пробелов и подтверждённое происхождение кода. Лицензия Ultra явно распространяется на вклад в форк, поэтому проверять нужно и происхождение заимствуемых компонентов. [Lumio README](https://github.com/Lumio-Research/hermes-agent-rs/blob/9a145877cacfde43efa07115536b71c51344de75/README.md), [Ultra v0.22.0](https://github.com/sheawinkler/hermes-agent-ultra/releases/tag/v0.22.0), [лицензия Ultra](https://github.com/sheawinkler/hermes-agent-ultra/blob/v0.22.0/LICENSE)

## Архитектура и границы модулей

В upstream `run_agent.py` предоставляет `AIAgent`, а ход диалога реализован в `agent/conversation_loop.py` и `agent/turn_*.py`. Он собирает prompt, выбирает провайдера, вызывает инструменты, управляет сжатием контекста и сохраняет результат. CLI, gateway, ACP и batch используют этот общий контур. У локальных CLI, TUI и Desktop один владелец канонической сессии в gateway. На диске данные разделены по профилям, а история хранится в SQLite с FTS5. [Архитектура upstream](https://hermes-agent.nousresearch.com/docs/developer-guide/architecture), [цикл диалога](https://hermes-agent.nousresearch.com/docs/developer-guide/agent-loop), [хранение сессий](https://hermes-agent.nousresearch.com/docs/developer-guide/session-storage), [локальные сессии gateway](https://hermes-agent.nousresearch.com/docs/developer-guide/gateway-local-sessions)

| Предлагаемое размещение | Ответственность и источники поведения |
| --- | --- |
| `crates/hermes-core/src/{turn,prompt,message}.rs` | Цикл диалога, типы сообщений и событий, сборка prompt, лимиты и сжатие. Источники `run_agent.py`, `agent/conversation_loop.py`, `agent/prompt_builder.py`, `agent/context_compressor.py`. |
| `crates/hermes-runtime/src/{config,providers,tools,storage,gateway,cron}/` | Конфигурация профиля, HTTP-адаптеры, политики и исполнение инструментов, SQLite и FTS5, владелец сессий, WebSocket и расписания. Источники `hermes_cli/`, `model_tools.py`, `tools/`, `persistence/`, `gateway/`, `tui_gateway/`, `cron/`. |
| `crates/hermes-cli/src/main.rs` | Команды, подключение к локальному владельцу сессии, печать событий и обработка сигналов. Источники `cli.py`, `hermes_cli/main.py`. |
| `crates/hermes-gui/` | Отдельное настольное приложение на GPUI. Интерфейс использует общий Rust runtime и локальный процесс-владелец профиля. [GPUI](https://gpui.rs/) |
| `compat/`, `crates/hermes-runtime/tests/` | Python-эталон, сценарии и фикстуры, сквозные тесты Rust CLI и gateway. Один сценарий используется для сравнения реализаций. |

Ядро принимает снимок настроек профиля, сообщения и интерфейсы провайдера и инструментов. Оно отдаёт упорядоченный поток событий хода и итоговый статус. Адаптер провайдера собирает частичные аргументы вызова инструмента до передачи ядру. Владелец сессии сохраняет сообщения и состояние запуска. CLI и внешние клиенты подписываются на события. Контекст профиля явно передаётся в фоновые задачи, провайдеры и дочерние процессы.

Кандидаты для стека — Tokio и `tokio-util` для асинхронного ввода-вывода и отмены, `serde`/`serde_json` для контрактов, `reqwest` с rustls для HTTP, `rusqlite` со встроенной SQLite, `clap` для CLI, `tracing` для логов и `rmcp` для MCP. При создании Cargo workspace закрепить toolchain и `Cargo.lock`. Выбрать YAML-парсер на фикстурах Hermes. При добавлении хранилища проверить `FTS5`, `trigram` и Online Backup на целевых сборках. Блокирующие транзакции выполнять вне потоков Tokio, обслуживающих запросы. [Tokio CancellationToken](https://docs.rs/tokio-util/latest/tokio_util/sync/struct.CancellationToken.html), [reqwest](https://docs.rs/reqwest/latest/reqwest/), [rusqlite](https://github.com/rusqlite/rusqlite), [Rust SDK для MCP](https://rust.sdk.modelcontextprotocol.io/)
